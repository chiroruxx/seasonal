# PR の作成・更新

`AGENTS.md` とメインからの依頼を確認する。本文のパスはプロジェクトルート基準。モードを「実装スタック」または「ストーリー改善PR」として指定された入力から判定し、モードの条件を満たさなければメインへ返す。

## 入力と対象の確認

### 実装スタック

- 対象ストーリー・計画のステップ、対象リポジトリ、ブランチとコミット、独立レビュー結果、`pre-pr-check` の成功結果と対象コミット、検証証跡、先行する PR・スタック、作成または更新する範囲を受け取る。
- 全ステップの実装・独立レビューと `pre-pr-check` が完了した後に、ステップごとの PR をまとめて作成する。途中のステップだけを先に公開しない。

### ストーリー改善PR

- 人間が受け入れたストーリー、改善の根拠と採用判断、レビュー済みの変更コミット・差分、独立レビュー結果、変更に対応する検証証跡、作成または更新するPRの範囲をメインから受け取る。
- 改善PRは通常の `master` 向けとし、受け入れ済みコミットや機能スタックのPRに含めない。単一の改善PRを作成し、機能スタックには登録しない。マージは人間が行う。
- `pre-pr-check` は実装スタックの条件であり、改善PRの必須条件にしない。改善差分に適用されるチェックとレビュー済み対象が一致することを確認する。

- いずれのモードでも、公開する差分とコミットがレビュー対象と一致し、必要な指摘対応・再レビュー・検証が完了しているかを確認する。未レビューの変更や対象の版に対応しない証跡があればメインへ返し、公開を進めない。対象コミットや差分が変わった場合は、メインへ返して必要な再検証・再レビューを受ける。実装スタックでは `pre-pr-check` も再確認する。確認済みのチェックを重複実行しない。
- 機能やテストは修正しない。実装修正が必要なら実装担当へ戻し、再検証・独立レビュー後の依頼を待つ。実装スタックの PR は受け入れテスト作成工程で作成しない。

## 作成と更新

- PR の作成・更新・確認には GitHub CLI の `gh` を使う。`gh pr create`、`gh pr edit`、`gh pr view` を使い、必要な API 操作は `gh api` で行う。利用環境の `gh` や API で必要な操作を行えない場合は、未完了の操作をメインへ報告する。
- 本文は [.github/pull_request_template.md](../../../.github/pull_request_template.md) に沿って作成する。各項目を実際の変更と証跡で埋め、対象外は理由を記載し、記入案内のコメントは除く。更新時は既存の本文を読み、人間が追記した情報を保持する。
- 完成した本文を実際の改行を持つ一時ファイルに書き、`gh pr create` または `gh pr edit` の `--body-file` で渡す。タイトルは解決する問題や実現する振る舞いを簡潔に表し、本文とは別に指定する。

- 実装スタックではレビュー済みコミット構成を保ち、ステップ単位で PR を作成する。既存 PR があれば対象を確認して更新し、同じステップの PR を重複作成しない。
- 実装スタックでは最初の PR は `master`、以降は前のステップのブランチを対象とし、GitHub の正式な Stacked Pull Requests として登録する。ストーリー改善PRでは `master` のみを対象とし、スタック登録しない。
- 実装スタックでは、base ブランチの依存関係を作るだけで完了とせず、GitHub のスタック表示または API で所属と順序を確認する。
- 実装スタックの本文では全体と当該 PR の差分を混同せず、そのステップの内容を記載する。
- 実装スタックの PR 作成後の修正は coder が行い、独立レビュー後のコミットを受け取って更新する。先行ステップの修正があれば後続の差分・依存順序への影響を確認する。後続コミットの書き換えなどでレビュー対象が変わる場合は、メインへ戻して再検証・再レビューの範囲を確認する。
- 実装スタックで利用環境が未対応、またはスタックへの登録を確認できない場合は、その状態をメインへ報告する。通常の依存 PR を正式なスタックとして報告しない。
- 実装スタックでは最後にスタック全体を提示し、別の総括 PR は追加しない。改善PRでは当該の単独PRを提示する。PR のマージは人間が行う。

## 報告

モードを明記し、PR の URL、対象、head・base と対象コミット、確認したレビュー・検証証跡をメインへ返す。実装スタックでは所属と順序も報告する。未完了・未確認事項も報告する。
