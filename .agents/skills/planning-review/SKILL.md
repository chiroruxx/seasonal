# 開発プランのレビュー

`AGENTS.md`、対象ストーリーと受け入れ条件、人間が確認した受け入れテスト、開発プラン、関連する確定仕様を確認する。作業担当とは別のエージェントとして、成果物を編集せずレビューする。本文のパスはプロジェクトルート基準。

文書の形式・明確さ・用語・参照の整合性は、`.agents/skills/document-review/SKILL.md` を併用して確認する。

## 確認すること

- すべての受け入れ条件を起点に、実現を担うステップと検証方法を追う。計画に対応表があるだけで十分とせず、作業内容と検証が条件を満たす具体性を持つか確かめる。複数ステップにまたがる条件も、全体として実現・検証できるかを見る。
- ステップが利用者に価値のある単位で分かれているかを確認する。UI・データ層などのレイヤーだけで分割していないか、利用者にとって何ができるようになるかが明確かを見る。
- 各ステップの目的と変更範囲が絞られ、人間が差分を理解してレビューできる大きさかを確認する。無関係な変更をまとめていないか、さらに価値を保って分割できないかを見る。1ステップを1コミットに固定しない。
- 計画された設計と作業を合わせて、受け入れ条件を実現できるかを評価する。テストに表れない必要な設計、データ・状態・境界の扱い、結合やストーリー全体の検証などに、実現を妨げる抜けがないかを見る。条件に不要な仕様を追加していないかも確認する。
- ステップ間の依存関係と順序が妥当かを確認する。必要な前提が先行ステップまたは既存の成果物で満たされ、循環や未計画の作業への依存がないかを見る。
- 未確定事項や根拠のない仮定を確定済みとして扱っていないかを確認する。実現可能性や分割を左右する判断が残る場合は、その影響と、実装を進める前に解決すべき事項を指摘する。

## 報告

指摘は対象の条件・ステップ・該当箇所と根拠を結び付け、重要度とともに示す。確認した条件の範囲、対応しない条件や不足する検証、分割・依存関係の問題、未確認事項を報告する。計画の妥当性の評価と、実装後のテスト成功を区別する。
