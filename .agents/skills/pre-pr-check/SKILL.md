# PR 作成前の最終確認

`AGENTS.md`、対象ストーリーと開発プラン、全ステップのブランチ・コミット、独立レビュー結果、hooks の検証証跡、公開予定の差分を確認する。全ステップの実装・指摘修正・再レビューが完了した後に reviewer が使う。本文のパスはプロジェクトルート基準。

コードや受け入れテストの内容を再レビューする工程ではなく、ストーリー全体を PR として公開できる状態か確認する。

## 確認すること

- すべてのステップの独立レビューと指摘対応が完了し、各ステップの head とレビュー・必要な検証の対象が対応しているかを確認する。
- 全ステップを含む最終 head に対し、定義された全チェックの成功証跡を確認する。formatter の整形チェック、linter、単体テスト、受け入れテストなどの実行対象・結果・対象コミットを追い、一部ファイルのチェックだけで全体成功としない。
- リポジトリ全体の受け入れテストが除外されず実行され、すべて成功しているかを確認する。通常チェックの成功だけでなく、フィルター・実行件数・スキップ結果も確認し、未実装テストが隠れていないかを見る。
- リポジトリ全体のテストに `@PendingAcceptance` がひとつも残っておらず、未実装の受け入れテストがないことを確認する。注釈の定義や説明文と、テストへの付与を区別する。ストーリーは直列で進めるため、別ストーリーを理由とする除外は認めない。
- 最終 head の全体検証と、各ステップのレビュー・必要な検証を区別し、PR の各 head・base と公開差分が確認対象に一致するかを見る。最終 head の成功を、異なるステップ head の検証証跡として流用しない。途中のステップ head には、その時点で計画上未実装の受け入れテストが残り得るため、全体成功や未実装ゼロは最終 head で確認する。

hooks がチェックを実行し、reviewer は証跡を確認する。有効な結果を重複実行しない。失敗・未実行・未発火・未接続や、除外・スキップされた受け入れテストを成功として扱わず、メインへ返す。

確認対象のコミットや差分が変わったら、影響する検証・独立レビューを更新して再確認する。実装修正は coder に戻し、この確認でコードやテストを変更しない。

## 報告

公開可否、各ステップと最終 head のコミット、対応するレビュー・全チェックの証跡、受け入れテストの実行範囲と未実装がない確認結果、未完了事項をメインへ返す。メインが成功を確認した後、別の作業エージェントへ `pull-request` スキルで PR 作成を依頼する。
