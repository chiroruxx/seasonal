# 旬データ調査の成果物形式

調査結果を追跡・分割処理するための中間形式。アプリ用 JSON のスキーマは確定しない。保存先は依頼で指定されたディレクトリを使う。

```text
<調査ディレクトリ>/
  raw/                 取得した原本
  sources.jsonl        出典の一覧
  observations.jsonl   出典ごとに抽出した観測事実
  issues.jsonl         不明点・不一致
  summary.md           範囲、件数、結果の要約
```

JSONL は UTF-8、1行1オブジェクト。各レコードに `schema_version: 1` を持たせる。不明な値は `null` とし、空文字列や推定値で埋めない。ID は調査内で一意かつ安定した文字列にし、並び順を変えても振り直さない。以下の項目を基本とし、元資料の追加属性は失わないよう拡張する。

## sources.jsonl

| 項目                        | 内容                                                         |
| --------------------------- | ------------------------------------------------------------ |
| source_id                   | 出典 ID                                                      |
| url                         | 原資料の URL                                                 |
| publisher / title           | 発行主体・資料名                                             |
| retrieved_at                | 実際の取得日時。ISO 8601、タイムゾーン付き                   |
| updated_at                  | 資料に示された更新日。未確認なら null                        |
| terms                       | 確認した利用条件の文言・根拠 URL。未確認なら null            |
| original_path               | 調査ディレクトリから raw 内原本への相対パス。未保存なら null |
| original_unavailable_reason | 未保存の理由。保存済みなら null                              |
| locator                     | 表・ページ・見出しなど資料内の参照箇所                       |

公開閲覧できることを再配布許可として記録しない。利用条件により原本を保存できない場合は、参照先・該当箇所と理由を残す。

## observations.jsonl

1件は1つの出典から抽出した事実。異なる出典を同一レコードに統合しない。

| 項目                                    | 内容                                                                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| observation_id                          | 観測レコード ID                                                                                                         |
| source_id / locator                     | sources への参照と、抽出した箇所                                                                                        |
| food                                    | 元資料の食材名                                                                                                          |
| region / origin / variety / cultivation | 地域・産地・品種・栽培方法。元資料にない属性は null                                                                     |
| definition                              | 元資料での旬の意味。収穫期・流通期など。未定義なら null                                                                 |
| raw_season                              | 旬の原文・表のセルなどを保持する文字列または構造。判読不能は null とし issues に記録                                    |
| period                                  | 解釈できる期間を元の粒度で整理した値。月・旬・日付、複数期間、年またぎを保持できる構造とする。確定解釈できなければ null |
| transformation                          | 抽出・変換した内容の記録。原文のままなら、その旨を記載                                                                  |

`period` は月配列に固定しない。`raw_season` の空欄・不明・「旬なし」を同一の意味にしない。データに応じて構造を定めた場合は、summary にその構造と解釈を記載する。

## issues.jsonl

| 項目                         | 内容                                      |
| ---------------------------- | ----------------------------------------- |
| issue_id                     | 不明点・不一致の ID                       |
| kind                         | unknown、conflict、unavailable などの区別 |
| source_ids / observation_ids | 該当する出典・レコード ID の配列          |
| detail                       | 不明点・不一致の内容と根拠                |
| status                       | unresolved または解決状況                 |
| resolution                   | 確認により解決した内容。未解決なら null   |

## summary.md

- 調査目的、食材・地域・出典の範囲、取得期間。
- 各 JSONL のレコード件数と原本保存の状況。
- 用いた期間表現・追加属性・変換方法。
- 不一致・不足・未取得、未確認の利用条件。
- データ構造や採用の提案。資料の事実と分けて記載する。

該当データのない JSONL は空ファイルでよい。summary に0件の理由を記載し、「該当なし」と「未調査」を区別する。書きかけの調査は、取得済みの範囲と残作業を示す。チャットには全データを貼らず、保存先と要約を返す。
