# 旬データレビュー

作業担当とは別のエージェントとして、依頼された出典・原データ・加工データ・変換記録を確認する。編集・再取得・再加工は行わず、必要なら理由を報告する。

調査データの形式は[成果物形式](../data-research/references/output-format.md)を参照する。アプリ用データをレビューする場合は、依頼で指定された確定スキーマと照合し、調査形式を勝手に適用しない。

## 確認すること

- JSONL の各行がオブジェクトとして読めること、スキーマ版、ID の一意性、出典参照・原本パス・抽出箇所を追跡できること。
- ファイルごとの件数と要約の一致、欠損の明示、重複や出典をまたぐ無断統合の有無。
- 取得日・資料更新日・利用条件の区別。公開閲覧だけを自由な再配布の根拠にしていないこと。
- 地域・産地・品種・定義・期間の粒度や年またぎが、原データから失われていないこと。
- 加工の結果と変換記録の一致。曖昧な期間や不一致を推測で解消していないこと。
- 元の文言を保った `raw_season` と、整理された期間・属性の対応。欠損値を季節なしと取り違えないこと。
- 出典情報が不明・原本未保存・未取得の箇所は、検証済みと扱わない。
- 既存の検証コマンドがあれば結果を確認する。未実行や失敗は明記する。新しい採用判断やスキーマ変更はレビューで決定しない。

全件の構造・参照確認と、出典照合を行った範囲を分けて報告する。大量データで一部を抽出確認した場合は、抽出方法・件数・未確認範囲を示し、全件の正しさを主張しない。指摘はレコード ID・出典・箇所・根拠を添え、報告文書自体の表現は `document-review` に分ける。
