# 文書レビュー

`AGENTS.md`、対象文書、依頼の根拠とレビュー範囲を確認する。作業担当とは別のエージェントとして、成果物を編集せず確認する。本文のパスはプロジェクトルート基準。

## 確認すること

- ユーザーの明示的な決定、既存の確定仕様、提案、未確定事項、実装済みの事実を区別する。人間の新しい指示より古い文書を優先しない。
- 対象ディレクトリからリポジトリルートまでの祖先にある `FORMAT.md` を、ルート側から確認する。近いディレクトリの具体的な指定を優先し、構成・必須項目・表記が形式に沿っているかを見る。兄弟の形式は適用しない。
- 形式がなければ依頼内容と同種の文書を基準とし、レビューのためだけに形式を新設しない。
- 関連文書との矛盾、古い参照先、不要なルールの重複、責務・完了条件・確認待ちの曖昧さを確認する。
- `docs/` のうち `docs/stories/` を除く文書に、経緯・比較案・未確定事項が混ざっていないかを見る。
- `docs/design/` のデザインシステムに、個別ページの表示内容・並び順が混ざっていないかを見る。
- ローカルリンクと画像参照を実ファイルで確認する。外部の事実は必要に応じて一次情報と照合する。
- hooks の文書用 formatter・linter の結果を確認し、対象の版に整形差分と lint エラーがない証拠を確かめる。確認済みのチェックを重複実行しない。hooks が未発火・未接続の場合は環境の不備としてメインへ返し、未設定・未実行・環境エラーを成功と区別する。
- formatter の純粋な整形変更は許可される。内容変更の承認と、改行用の行末スペースの保持を確認する。
- 調査報告の文章は文書レビューの対象だが、生データ・加工データの妥当性は `data-review` で確認する。レビュー依頼から再取得や加工を始めない。

## 報告

指摘をファイル・行・根拠とともに示す。意味の誤りや矛盾と、任意の表現改善を区別する。指摘がなくても、確認範囲、適用形式、チェック結果、未確認事項を報告する。
