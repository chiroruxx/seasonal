# 食材データの管理

## 基本方針

アプリ同梱の JSON で食材情報を管理し、画像は別ファイルで同梱する。

## データの大枠

- 食材 ID。
- 表示名。
- 旬の情報。
- 一覧用イラストのパス。
- 選び方の説明とイラストのパスを組にした配列。
- 情報の出典と確認日。

画像パスはアプリの assets を基準とした相対パスにする。JSON に画像のバイナリや端末固有の絶対パスを埋め込まない。検証時に参照先の存在を確認する。

## 旬の情報

旬のデータ構造は、元データを確認してから決める。月の配列だけで足りるとは現時点では判断しない。

- 元データの期間の粒度、地域・産地、品種などの区別を確認する。
- 必要な情報を失わない保存形式を選ぶ。
- 保存する情報の粒度と、画面で表示・抽出する粒度を分けて考える。
- 「いまが旬」「そろそろ旬」の判定方法は、元データの意味と粒度に合わせて具体化する。

月単位で十分であれば `seasonMonths` の配列を候補とする。より詳細な期間を持つ場合は、その情報から画面用の旬の状態を求める。

## 元データの確認事項

- 出典と利用条件。
- 旬の定義と、期間の表し方。
- 対象地域・産地・品種の範囲。
- 情報の更新日と、内容を確認した日。

旬や選び方の正しさは出典に照らして人が確認する。JSON の形式・値の整合性・画像参照は自動テストで確認する。
